В настоящем препринте представлено формальное описание языка программирования ПОПЛАН. Грамматические конструкции описаны при помощи синтаксических графов. Семантика во многих случаях просто проиллюстрирована соответствующими примерами. Первая часть описания была посвящена синтаксису и семантике деклараций, функций и основных управляющих структур. Во второй части описываются структуры данных, макро-средства и возможности ввода-вывода.

A precise description of the programming language POPLAN is presented in this issue. To describe the syntactic elements of the language, syntax graphs are used. In many cases the semantics is simply illustrated by the relevant examples. The first part of the description was devoted to the syntax and semantics of the declarations, functions, and the main control structures. In the second part the data structures, macros, and the input-output facilities are described.

### ПРЕДИСЛОВИЕ

Первая часть формального описания языка ПОПЛАН была посвящена главным образом тем чертам ПОПЛАНа, которые определяют его сходство с такими языками как АЛГОЛ или ФОРТРАН. ## 6. СТРУКТУРЫ ДАННЫХ

### 6.1. Общие замечания

Структурой данных называется составной элемент, содержащий другие элементы в качестве компонент.

Полезно сказать несколько слов о представлении простых и составных элементов в памяти ЭВМ. Простые элементы (§ 2.1) представляются своей числовой величиной, а составные — адресом области памяти, где хранятся их компоненты. Стандартная операция `"="`, примененная к составным элементам, дает значение `TRUE` тогда и только тогда, когда эти адреса равны.

Число компонент структуры не может равняться нулю (исключение — пустая цепочка, см. § 7.5).

Полезно ввести понятие размера компоненты структуры. Если эта компонента должна быть целым числом в диапазоне [0, 2ⁿ − 1], 0 ≤ n ≤ 40, то говорят, что она имеет размер n. Размер 0 показывает, что компонента может содержать любой элемент (говорят, что компонента является полным элементом). Очевидно, для хранения компоненты размера n достаточно n битов; под полный элемент отводится полное слово.

Составные элементы, имеющие одинаковую структуру, объединяются в классы. С каждым таким классом ассоциируется некоторый элемент (обычно слово). Стандартная спаренная функция `DATAWORD`, примененная к структуре данных, порождает или изменяет элемент, ассоциированный с классом, которому эта структура принадлежит. Функция применима также к целым и вещественным числам и дает `"INTEGER"` и `"REAL"` соответственно. С помощью функции `DATAWORD` нельзя изменить слова, ассоциированные с числами и стандартными классами структур. (К стандартным классам относятся ссылки, § 7.1, пары, § 7.2, слова, § 7.4, полные стрипы и цепочки, § 7.5, функции, § 7.7).

`DATAWORD ∈ элемент = => элемент`. Стандартная функция

`SAMEDATA ∈ элемент, элемент => логическое значение`

дает значение `TRUE`, если элементы принадлежат одному классу.

Структуры данных делятся на две большие группы: неиндексированные и индексированные структуры. Элементы первой группы называются записями, второй — стрипами. И к записям, и к стрипам применимы следующие три стандартные функции:

`DATALIST ∈ запись или стрип => список`

преобразует структуру данных в список ее компонент (о списках см. § 7.3).

`APPDATA ∈ запись или стрип, функция => элемент, ..., элемент`

применяет ко всем компонентам структуры данную функцию.

`COPY ∈ запись или стрип => запись или стрип`

копирует структуру на верхнем уровне, то есть формирует элемент, указывающий на новую область памяти, содержащую те же компоненты. Скопированный элемент не равен исходному.

### 6.2. Записи

Для того, чтобы иметь возможность работать с неиндексированной структурой данных, необходим следующий набор функций:

1) функция для создания записи (конструктор)

   `∈ элемент, ..., элемент => запись`

2) обратная функция (деструктор) `∈ запись => элемент, ..., элемент`

3) спаренные функции для выборки или изменения отдельных компонент записи `∈ запись = => элемент`

Чтобы описать структуру записи, нужно перечислить размеры ее компонент.

В ПОПЛАНе имеются три стандартных класса записей (ссылки, пары и слова). Кроме того, можно создавать новые классы. Для этого используется стандартная функция `RECORDFNS` с двумя аргументами: элемент, который мы хотим ассоциировать с новым классом записей и список размеров компонент. Результатами будут конструктор, деструктор и спаренные функции для работы с каждой компонентой, поступающие на стек в порядке перечисления размеров компонент. Таким образом, если запись имеет n компонент, то у функции `RECORDFNS` будет n+2 результатов.

`RECORDFNS ∈ элемент, список => конструктор, деструктор, спаренная функция, ..., спаренная функция`

Пример.

Пусть нужно хранить о людях следующую информацию: фамилию, семейное положение и число детей.

<!-- PDF page 5: printed pages 6–7 -->

```pop2
vars CREATE DESTROY NAME MARRIED NCHILD;
RECORDFNS( "PERSON", [0 1 4])
-> NCHILD -> MARRIED -> NAME -> DESTROY -> CREATE;
vars BILL;
CREATE ( "SMITH", TRUE, 2) -> BILL;
DESTROY( BILL )=>
    ** SMITH, 1, 2
function BIRTH X => Y;
   comment рождение ребенка у человека X. Результат
           -запись, описывающая новорожденного;
   CREATE ( NAME (X), 0, 0) -> Y;
   NCHILD(X)+1 -> NCHILD(X);
end;
vars BABY; BIRTH( BILL ) -> BABY;
NAME( BABY ) =>
    ** SMITH
NCHILD( BILL ) =>
    ** 3
```

### 6.3. Стрипы

Для того, чтобы работать с индексированной структурой данных, каковой является стрип, необходимы следующие функции:

1) функция для создания стрипа (инициатор)

   `∈ целое => стрип`

   Она создает стрип с данным числом компонент, значения которых не определены;

2) спаренная функция для выборки или изменения компоненты с данным номером

   `∈ целое, стрип = => элемент`;

   компоненты стрипа нумеруются начиная с 1.

Стрипы с одинаковым размером компонент объединяются в класс. Заметим, что стрипы данного класса могут иметь разное число компонент.

Имеются два стандартных класса стрипов: полные и цепочки (см. § 7.5). Для создания новых классов служит стандартная функция `STRIPFNS`. Она имеет два аргумента: элемент, ассоциируемый с новым классом, и размер компонент. Результатами ее являются инициатор и спаренная функция для работы с отдельными компонентами.

`STRIPFNS ∈ элемент, размер => инициатор, спаренная функция`

Стандартная функция `DATALENGTH` позволяет узнать число компонент стрипа.

`DATALENGTH ∈ стрип => целое`.

Пример.

Реализуем процедуру выявления простых чисел с помощью решета Эратосфена. Для этой цели подходит класс стрипов, размер компонент которых равен 1.

```pop2
vars BSUB BINIT ST N;
STRIPFNS( "BIT", 1) -> BSUB -> BINIT;
function PRIME N => BS;
  vars BS I J J1;
  BINIT( N ) -> BS;
comment функция PRIME выявляет простые числа от 2 до N;
  INTOF( SQRT( N+0.5 ) ) -> NS;
  forall I 2 1 N 1 -> BSUB( I, BS ) close;

comment            сделали начальное заполнение массива. В сле-
дующем цикле помечаем все составные числа от 4 до N нулем;
  forall I 2 1 NS
    if BSUB( I, BS ) then I*I -> J1;
      forall J J1 I N 0 -> BSUB( J, BS ) close
    close
  close
end;
PRIME( 100 ) -> ST;
BSUB( 83, ST ) =>
    ** 1
comment то есть 83 - простое число;
BSUB( 39, ST ) =>
    ** 0
DATALENGTH( ST ) =>
    ** 100
```

### 6.4. Сбор мусора

Всякий раз, когда для создания новой структуры не хватает свободной памяти, вызывается специальная программа сбора мусора. Она отмечает области памяти, доступные из программы, а оставшиеся блоки связывает в список свободного пространства. (Перед началом работы ПОПЛАН-системы этот список содержит один блок, состоящий примерно из 14000 ячеек.) Поэтому, если программист хочет снова использовать память, занятую какой-либо структурой данных, необходимо сделать ее недоступной из программы. Например, если эта структура была значением переменной, этой переменной можно присвоить, скажем, 0. Заметим, что отмена идентификатора не дает программе сбора мусора права разрушить значение соответствующей переменной, ибо она может использоваться как нелокальная в некоторой функции.

## 7. СТАНДАРТНЫЕ СТРУКТУРЫ

В этом разделе описываются имеющиеся в ПОПЛАНе стандартные классы структур.

### 7.1. Ссылки

Ссылки — стандартный класс записей, имеющих в качестве единственной компоненты полный элемент. С классом ассоциировано слово `"REF"`. Для работы со ссылками имеются следующие стандартные функции:

| | |
|---|---|
| конструктор | `CONSREF ∈ элемент => ссылка` |
| деструктор | `DESTREF ∈ ссылка => элемент` |
| спаренная функция | `CONT ∈ ссылка = => элемент` |

Ссылки полезно использовать для получения различных побочных эффектов.

Пример.

```pop2
function COUNTER X;
  X.CONT + 1 -> X.CONT
end;
function ERR X;
  X + 1 -> X
end;
vars A;
0 -> A; ERR( A ); A =>
    ** 0
0.CONSREF -> A; COUNTER( A ); A.DESTREF =>
    ** 1

comment       функция ERR не может изменить значение A,
ибо в ПОПЛАНе параметры передаются по значению. Функция
COUNTER       также не меняет значение фактического параметра
(ссылка продолжает указывать на ту же ячейку памяти, меняется
лишь содержимое этой ячейки).;
```

### 7.2. Пары

Пары — стандартный класс записей, двумя компонентами которых

<!-- PDF page 7: printed pages 10–11 -->

являются полные элементы. С классом ассоциировано слово `"PAIR"`.

Функции для работы с парами:

| | |
|---|---|
| конструктор | `CONSPAIR ∈ элемент, элемент => пара` |
| деструктор | `DESTPAIR ∈ пара => элемент, элемент` |
| спаренные функции | `FRONT ∈ пара = => элемент` |
| | `BACK ∈ пара = => элемент` |

Атомом называется элемент, не являющийся парой. Для распознавания атомов служит стандартная функция

`ATOM ∈ элемент => логическое значение`.

В основном используется частный случай пар — списки (см. следующий параграф). Другой пример использования пар приведен в [1], § 3.2.

### 7.3. Списки

Список может быть пустым или непустым. Пустым списком называется каждый из трех следующих элементов:

1) Слово `"NIL"` (стандартная переменная `NIL` имеет его своим значением).
2) Пара, `FRONT`-компонентой которой является `FALSE`, а `BACK`-компонентой — функция.
3) Пара, `FRONT`-компонентой которой является не `FALSE`, а `BACK`-компонентой — функция без аргументов, имеющая своим результатом `TERMIN`.

Непустым списком называется каждый из двух следующих элементов:

a) пара, `BACK`-компонентой которой является список;

b) пара, `FRONT`-компонентой которой является не `FALSE`, а `BACK`-компонентой — функция без аргументов и с одним результатом, отличным от `TERMIN`.

В случае (b) мы получаем так называемый динамический список. Его элементами являются результаты, получающиеся при последовательных обращениях к функции. Элемент `TERMIN` — признак конца динамического списка. Функция такого типа (без аргументов и с одним результатом) называется *поставщиком*.

Для работы с непустыми списками имеются следующие функции:

| | |
|---|---|
| конструктор | `CONS ∈ элемент, список => непустой список` |
| деструктор | `DEST ∈ непустой список => элемент, список` |
| спаренные функции | `HD ∈ непустой список = => элемент` |
| | `TL ∈ непустой список = => элемент` |

Подчеркнем, что функции `HD` и `TL` устроены таким образом, что с их помощью нельзя различить списки типов (a) и (b).

Функция `CONS` порождает непустой список типа (a). Для создания списков типа (b) имеется стандартная функция

`FNTOLIST ∈ функция => список`

Для распознавания пустых списков служит стандартная функция

`NULL ∈ список => логическое значение`

Для распознавания непустых списков имеется стандартная функция

`ISLINK ∈ элемент => логическое значение`

Пустой список состоит из нуля элементов. Первый элемент непустого списка `L` есть `HD( L )`, а оставшиеся элементы являются элементами списка `TL( L )`. Для подсчета числа элементов в списке имеется стандартная функция

`LENGTH ∈ список => целое`

Для примера покажем, как ее можно было бы реализовать на ПОПЛАНе.

Пример.

```pop2
function LENGTH LIST => N;
   0 -> N;
   loopif LIST .ISLINK then
       N+1 -> N; LIST .TL -> LIST
   close
end;
```

Для распознавания списков (в том числе и пустых) служит стандартная функция

`ISLIST ∈ элемент => логическое значение`

Для создания списков имеются две специальные синтаксические формы — списочные константы и списочные выражения, см. Д44, Д45. Здесь мы ограничимся двумя примерами.

```pop2
[1 2 [3 4]] 'ПРИМЕР СПИСОЧНОЙ КОНСТАНТЫ ИЗ ЧЕТЫРЕХ ЭЛЕМЕНТОВ';

[% 17 + X, 4-2, [% 12,14 %], 19 %];
```

Каждый из написанных выше списков состоит из четырех элементов, причем в обоих случаях третий элемент сам является списком.

<!-- PDF page 8: printed pages 12–13 -->

Имеются также следующие стандартные функции и операции

`::` (синоним функции `CONS`, но операция приоритета 2)

`<> ∈ список, список => список`

(конкатенация списков, первый из них копируется; операция приоритета 2)

`MAPLIST ∈ список, функция => список`

(ко всем элементам исходного списка применяется функция, которая должна иметь один аргумент и один результат; из результатов строится новый список)

Пример.

```pop2
MAPLIST ( [1 2 3], lambda X; X+1 end ) =>

   ** [2 3 4]
```

`APPLIST ∈ список, функция => элемент, ..., элемент`

(аналогична функции `MAPLIST`, только результаты не используются для построения списка, а просто помещаются на стек)

Пример.

```pop2
APPLIST ( [1 2 3], lambda X; X+1 end ) =>
  ** 2, 3, 4
```

Иногда бывает полезно обратить список, т.е. переписать его в обратном порядке. Для обращения списка на верхнем уровне в ПОПЛАНе имеется стандартная функция

`REV ∈ список => список`

Пример.

```pop2
[1 2 [3 4]]. REV =>
   ** [[3 4] 2 1]
```

Чтобы скопировать список на верхнем уровне, можно воспользоваться стандартной функцией.

`COPYLIST ∈ список => список`

Заметим, что функция `COPY`, в отличие от `COPYLIST` копирует лишь первую пару в списке.

Пример.

```pop2
vars A B C; [1 2 3] -> A;
COPY (A) -> B; COPYLIST (A) -> C; A, B, C =>
   ** [1 2 3], [1 2 3], [1 2 3]
4 -> A.HD; A, B, C =>
   ** [4 2 3], [1 2 3], [1 2 3]
5 -> A.TL.HD; A, B, C =>
   ** [4 5 3], [1 5 3], [1 2 3]
[[1 2] 3 4] -> A; COPYLIST (A) -> C; A, C =>
   ** [[1 2] 3 4], [[1 2] 3 4]
6 -> A.HD.HD; A, C =>
   ** [[6 2] 3 4], [[6 2] 3 4]
```

Чтобы проверить, совпадают ли элементы двух списков, можно воспользоваться стандартной функцией

`EQUAL ∈ список, список => логическое значение`

Функция `EQUAL` производит сравнения на любом, а не только верхнем, уровне.

Пример.

```pop2
[1 [2 3]] = [1 [2 3]] =>
   ** 0
[1 [2 3]], [1 [2 3]]. EQUAL =>
   ** 1
```

В качестве еще одного примера рассмотрим, как можно было бы реализовать на ПОПЛАНе стандартные функции `APPDATA` и `REV`.

Пример.

```pop2
function APPDATA STRUCTURE F;
   STRUCTURE . DATALIST, F . APPLIST
end;
function REV LISTIN => LISTOUT;
   NIL -> LISTOUT;
   loopif LISTIN.ISLINK then
      LISTIN.DEST -> LISTIN; :: LISTOUT -> LISTOUT
   close
end;

comment       функция REV отщепляет по элементу от спис-
ка LISTIN и присоединяет его в начало списка LISTOUT;
```

### 7.4. Слова

Слова — стандартный класс записей; они имеют 6 компонент размера 8 (литеры) и одну компоненту, являющуюся полным элементом, с

<!-- PDF page 9: printed pages 14–15 -->

названием `MEANING`. С классом ассоциировано слово `"WORD"`.

Для работы со словами имеются следующие функции:

| | |
|---|---|
| конструктор | `CONSWORD ∈ литера, ..., литера, целое => слово` |
| деструктор | `DESTWORD ∈ слово => литера, ..., литера, целое` |
| функция для выборки | `CHARWORD ∈ слово, целое => литера` |
| спаренная функция | `MEANING ∈ слово = => элемент` |

Литера — это целое число в диапазоне [0, 255]. Литеры в слове нумеруются слева направо, начиная с 1. Для создания слова не нужно задавать значение компоненты `MEANING`; она не определена, пока ей не будет присвоено какое-либо значение. Изменить отдельные литеры слова нельзя.

Для распознавания слов служит стандартная функция

`ISWORD ∈ элемент => логическое значение`

Когда к слову применяется функция `DATALIST`, получается список его литер.

В программе можно создавать константы типа слов, для этого слово нужно взять в двойные кавычки (см. диаграмму 49).

Пример.

```pop2
vars X; "WORD" -> X; X =>
   ** WORD
```

Слова могут быть также компонентами списочных констант. В этом случае их не нужно заключать в кавычки.

Пример.

`[WORD1 WORD2 WORD3]`

является списком из трех слов.

Значимыми являются лишь первые шесть литер слова.

Примечание. Слова стандартизованы в том смысле, что два слова равны тогда, когда они имеют совпадающие литеры. Этим слова отличаются от записей других классов.

Пример.

```pop2
"ABCD" = "ABCD" =>
    ** 1
"VARIABLE1" = "VARIABLE2" =>
    ** 1
DATALIST (X) = DATALIST (X) =>
    ** 0
```

### 7.5. Полные стрипы и стрипы из литер (цепочки)

Два класса стрипов являются стандартными.

*Полные стрипы* имеют нулевой размер компонент. С классом ассоциировано слово `"STRIP"`. Функции для работы с полными стрипами:

| | |
|---|---|
| инициатор | `INIT ∈ целое => полный стрип` |
| спаренная функция | `SUBSCR ∈ целое, полный стрип = => элемент` |

В качестве примера опишем функцию, осуществляющую в полном стрипе последовательный поиск нужного элемента. Для удобства будем предполагать, что функция может использовать последний элемент стрипа для своих нужд.

Пример.

```pop2
function SEARCH KEY STRIP => N;
comment       результатом функции является номер элемента,
равного искомому или 0, если такого элемента нет;
   KEY -> SUBSCR (STRIP.DATALENGTH, STRIP);
   1 -> N;
   loopif KEY /= SUBSCR (N, STRIP) then
      N+1 -> N
   close;
   if N = STRIP.DATALENGTH then 0 -> N close
end;
```

*Стрипы из литер* (цепочки) имеют размер компонент, равный 8. С классом ассоциировано слово `"CSTRIP"`. Функции для работы с цепочками:

| | |
|---|---|
| инициатор | `INITC ∈ целое => цепочка` |
| спаренная функция | `SUBSCC ∈ целое, цепочка = => литера` |

Правила создания [неразборчиво: часть слова, вероятно «цепочек»] во время компиляции приведены на диаграмме 47.

Стандартная функция [неразборчиво] печатает [неразборчиво] кавычками, а функция `PRSTRING` [неразборчиво: окончание строки сильно выцвело].

<!-- PDF page 10: printed pages 16–17 -->

Пример.

```pop2
'CHARACTER STRIP'.PRSTRING;
     CHARACTER STRIP
'ABCD'.PR;
    'ABCD'
```

Если необходимо употребить кавычку в стрипе из литер, ее следует повторить дважды.

Пример.

```pop2
'AB''CD' =>
   ** 'AB'CD'
vars X; 'A''B' -> X; X.DATALENGTH =>
** 3
```

### 7.6. Массивы

Массивом называется спаренная функция такого вида

массив ∈ целое, ..., целое = => компонента массива

(n целых).

Число n называется размерностью массива, а целые, перечисленные в левой части — индексами.

Имеется стандартная функция для создания массива с компонентами данного размера.

`NEWANYARRAY ∈ список, функция, инициатор, спаренная функция => массив`

Первым аргументом является список целых чисел, указывающих попеременно нижнюю и верхнюю границу изменения каждого индекса. Второй аргумент — функция с n аргументами (n — размерность массива), являющимися целыми числами, и с одним результатом — используется для присваивания компонентам массива начальных значений. Инициатор и спаренная функция должны быть предназначены для работы со стрипами, имеющими тот же размер компонент, что и компоненты массива.

Пример.

```pop2
vars A;
NEWANYARRAY ( [1 5 1 10], lambda I J; I+J end,
    INITC, SUBSCC) -> A;
comment       мы создали массив литер размера 5 x 10. В ка-
честве начального значения (i, j)-й компоненте присвоена сумма
i + j;
A (2, 3) =>
    ** 5
17 -> A (4, 7); A (4, 7) =>
    ** 17
```

Для создания массива из полных элементов имеется стандартная функция

`NEWARRAY ∈ список, функция => массив`

Она эквивалентна замкнутой функции

`NEWANYARRAY (% INIT, SUBSCR %)`

Стандартная функция

`BOUNDSLIST ∈ массив = => список`

выбирает или меняет список границ изменения индексов массивов, созданных с помощью `NEWANYARRAY` или `NEWARRAY`.

Пример.

```pop2
BOUNDSLIST (A) =>
 ** [1 5 1 10]
[1 5 1 5] -> A.BOUNDSLIST; A (2, 3) =>
    ** 9
```

### 7.7. Функции

Функции можно рассматривать как структуры данных. С этим классом ассоциировано слово `"FUNCTION"`. Способы создания функций описаны в §§ 4.1 и 4.3.

Функция имеет компоненту (полный элемент), которую можно использовать для запоминания какой-либо информации о функции. Для работы с этой компонентой служит стандартная спаренная функция

`FNPROPS ∈ функция = => элемент`

Для спаривания функций (см. § 4.4) служит компонента, с которой работает стандартная спаренная функция

`UPDATER ∈ функция = => элемент`

Если функция получена с помощью частичного применения, то посредством стандартной спаренной функции

`FROZVAL ∈ целое, замкнутая функция = => элемент`

можно выбирать или изменять значения замороженных параметров. В

<!-- PDF page 11: printed pages 18–19 -->

применении к таким функциям `DATALIST` дает список замороженных значений.

Для выборки или изменения функции, из которой данная функция была получена частичным применением, служит стандартная спаренная функция

`FNPART ∈ замкнутая функция = => функция`

Для распознавания функций служит стандартная функция

`ISFUNC ∈ элемент => логическое значение`

Пример.

```pop2
vars INCR; nonop + (% 1 %) -> INCR;
INCR (3) =>
    ** 4
2 -> FROZVAL (1, INCR); INCR (3) =>
    ** 5
nonop - -> FNPART (INCR); INCR (7) =>
    ** 5
```

Всякая функция является либо защищенной, либо незащищенной. У защищенной функции нельзя поменять ни одну из компонент, с которыми работают функции `FNPROPS`, `UPDATER`, `FROZVAL`, `FNPART`. Все стандартные функции ПОПЛАН-системы защищены. Все функции, которые тем или иным способом создаются пользователем, незащищенные. Примеры

```pop2
vars S; SIN -> S; "SINUS" -> S.FNPROPS;
*** ОШИБКА 12032
ПРИСВАИВАНИЕ ЗАЩИЩЕННОЙ ФУНКЦИИ
660000000006761 FUNCTI

SETPOP
CUCHIN -> CUCHOUT.UPDATER;
*** ОШИБКА 12032
ПРИСВАИВАНИЕ ЗАЩИЩЕННОЙ ФУНКЦИИ
660000000007475 FUNCTI

SETPOP

comment несмотря на то, что переменная CUCHOUT не защи-
щена, функция, которая является ее значением при входе в
ПОПЛАН-систему, защищена;
```

## 8. ВВОД-ВЫВОД

В этом разделе описываются средства языка ПОПЛАН для обмена символьной информацией с внешними устройствами. Бессимвольный обмен будет описан в другом выпуске, там же будет дана более подробная информация о символьном обмене.

### 8.1. Файлы. Потребители и поставщики литер

Введем несколько понятий. Поставщиком называется функция `∈ () => элемент`, в частности, поставщиком литер называется функция `∈ () => литера`. (Напомним, что литерой в ПОПЛАНе называется целое число — код внешнего представления литеры; специального литерного типа элементов не существует). Потребителем называется функция `∈ элемент => ()`; потребитель литер — функция `∈ литера => ()`. Последовательность литер, записанную на внешнем устройстве, мы будем называть файлом. Перед работой с файлом его следует открыть. После этого можно читать (или записывать) литеры файла последовательно по одной при каждом обращении к функции-поставщику (или потребителю) литер. При обращении к поставщику литер мы получаем в качестве результата очередную литеру файла. При обращении к потребителю литер литера, являющаяся его аргументом, записывается в файл. Файл в конце концов должен быть закрыт. После закрытия доступ к этому файлу прекращается.

Для открытия файла и создания соответствующего поставщика (потребителя), а также для закрытия файла используется функция

`POPMESS ∈ список => элемент, ..., элемент`

Список определяет файл, с которым мы будем работать, возможные варианты его задания см. в прил. 2. Результатом функции `POPMESS` при открытии файла является поставщик или потребитель литер, при закрытии файла `POPMESS` не имеет результатов.

Примеры:

```pop2
POPMESS([TI]);
```

Результатом является поставщик литер со стандартного терминала.

```pop2
POPMESS([% "MO", 8:260000+N, M, 8:260020 %]);
```

Результатом будет потребитель литер для вывода на МБ с математи-

<!-- PDF page 12: printed pages 20–21 -->

ческим номером 26; переменные N и M задают соответственно номер зоны и номер ячейки в этой зоне, с которых начинается файл вывода. Файл может занимать зоны по 17 включительно.

Последней литерой файла ввода должна быть специальная стоп-литера, являющаяся признаком конца файла. (В настоящей реализации стоп-литерой является литера надчеркивание. На перфокартах наряду с надчеркиванием можно использовать литеру 'вычитание'.) Когда поставщик литер из файла ввода прочитывает стоп-литеру, он выдает ее в качестве результата, сообщая тем самым программе об окончании файла, и закрывает этот файл. Дальнейшие обращения к этому поставщику литер запрещаются. Файл ввода на магнитных носителях, кроме того, закрывается автоматически, если будет достигнута граница, установленная при его открытии (см. прил. 2). В этом случае поставщик литер выдает также и стоп-литеру. Файл вывода закрывается, когда аргументом потребителя литер будет стоп-литера. Файл вывода на магнитный носитель, кроме того, закрывается при достижении установленной границы, но в этом случае (в отличие от обычного закрытия) в файл не записывается признак конца, поэтому для нормального чтения такого файла необходимо при открытии его на чтение указать ту же границу.

Как файл ввода, так и файл вывода может быть закрыт с помощью функции `POPMESS`. Для этого ее аргументом должен быть список из двух элементов. Первый из них — слово `CLOSE`, второй — функция для работы с этим файлом (поставщик или потребитель литер).

### 8.2. Библиотека ПОПЛАН-программ

В качестве ПОПЛАН-библиотеки используется файловая система ДИМОНа (см. [5]). В ПОПЛАНе нет средств редактирования файлов ДИМОНа, т.к. развитые средства редактирования предоставляет сам ДИМОН. Имеется возможность прочитать файл ДИМОНа. Для этого используется функция

`LIBRARY ∈ список => функция`.

Аргументом является список из двух элементов. Первый элемент — слово, задает идентификатор пользователя в смысле ДИМОНа (см. [5]), второй элемент — слово, задает имя файла. Результатом `LIBRARY` является поставщик литер из данного файла. В ДИМОНе имеется библиотека (пользователь) `POPLIB`, содержащая библиотеку ПОПЛАН-программ, в частности, систему отладки ПОПЛАН-программ (имя файла `DEBUG`, см. прил. 5), набор программ для редактирования символьной информации (имя файла `POPEDIT`), программу для игры в трехмерные крестики-нолики (имя файла `FOURS`) и др.

Потребитель литер для вывода в файл ДИМОНа может быть получен с помощью функции `POPMESS`. Для этого ее аргументом должен быть список из трех слов: слова ДО, идентификатора пользователя и имени файла. Файл, в который мы собираемся выводить информацию, должен уже существовать в ДИМОНе. Если он не пуст, то выводимая информация дописывается в конец файла.

Пример.

Перепись программы игры в крестики-нолики в файл пользователя:

```pop2
vars CHAR IN OUT;
[POPLIB FOURS].LIBRARY -> IN;
[ДО ИВАНОВ ИГРА].POPMESS -> OUT;
comment       создали поставщик литер из файла FOURS в
библиотеке POPLIB и потребитель литер для вывода в файл
ИГРА в библиотеке ИВАНОВ;
loopif(.IN -> CHAR; CHAR.OUT; CHAR/=HALTCODE) then close;

comment       переписали весь файл (переменная HALTCODE
содержит код стоп-литеры);
```

### 8.3. Стандартные файлы ввода и вывода

Стандартные файлы ввода и вывода, автоматически открываемые при вызове ПОПЛАН-системы, используются для коммуникации ПОПЛАН-системы с пользователем. В стандартный файл вывода выдаются со-

<!-- PDF page 13: printed pages 22–23 -->

общения об ошибках, а также все печатаемые результаты, до тех пор пока пользователь не изменит файл для вывода результатов. В начале работы и после каждой ошибки транслятор будет обрабатывать программу из стандартного файла ввода, пока пользователь не укажет другой файл для трансляции. Поставщик литер стандартного файла ввода находится в переменной `CHARIN`

`CHARIN ∈ () => литера`

Потребитель литер для стандартного выводимого файла находится в переменной `CHAROUT`

`CHAROUT ∈ литера => ()`

В переменной `CUCHOUT` находится потребитель литер для текущего файла вывода. Первоначально ее значение совпадает с `CHAROUT`, однако переменная `CUCHOUT` не защищенная, и ей может быть присвоен любой потребитель литер. Все стандартные функции печати (печатающая стрелка и функции `PR`, `PRSTRING`, `PRINT`, `PRREAL`, `SP`, `NL`, описанные ниже в § 8.4) выводят литеры, обращаясь к `CUCHOUT`. При выдаче сообщения об ошибке и применении функции `SETPOP` выполняется присваивание `CHAROUT -> CUCHOUT`, т.е. текущий файл вывода восстанавливает стандартное значение. Аналогично, имеется незащищенная переменная `CUCHIN`, значение которой первоначально совпадает с `CHARIN`. Ее рекомендуется использовать для написания функций, вводящих литеры из некоторого текущего вводимого файла. Сама ПОПЛАН-система не использует переменную `CUCHIN`.

Стандартные файлы ввода и вывода не требуют открытия и не могут быть закрыты.

Стандартные файлы ввода и вывода располагаются на стандартных устройствах ввода и вывода, которыми, в зависимости от запуска ПОПЛАН-системы, могут быть устройства ввода с перфокарт и АЦПУ или терминал (устройство ввода/вывода). По мере развития ПОПЛАН-системы могут появиться и другие возможности.

### 8.4. Потребители элементов

Кроме печатающей стрелки, с которой вы уже знакомы (см. также ниже) имеется еще несколько функций для вывода элементов в текущий файл вывода. Функции

`NL, SP все ∈ целое => ()`

выводят пробелы (`SP`) или переводы строк (`NL`) в количестве, указываемом неотрицательным целым числом — аргументом.

Функция

`PR ∈ элемент => ()`

печатает (т.е. выводит в текущий файл вывода) произвольный элемент. Отрицательные числа печатаются со знаком минус, неотрицательные — с пробелом перед ними; списки печатаются заключенными в квадратные скобки; слова печатаются без кавычек; цепочки литер — с кавычками; значение `UNDEF` печатается как НЕОПРЕДЕЛЕН; печать `TERMIN` вызывает вывод стоп-литеры. Для остальных структур данных выводится слово, ассоциированное с ними (результат применения к ним функции `DATAWORD`), а не компоненты структуры. Например:

```pop2
vars X; CONSPAIR("CAT", "КОТ") -> X; X.PR;
```

Будет напечатано слово

```text
PAIR
```

Для распечатки компонент структуры данных удобно пользоваться функцией `DATALIST`:

```pop2
X.DATALIST.PR;
```

Будет напечатано

```text
[CAT КОТ]
```

Функция

`PRINT ∈ элемент => элемент`

определяется как

```pop2
function PRINT X; X.PR; X end;
```

т.е. печатаемое значение остается на стеке.

Стандартная функция

`PRREAL ∈ вещественное, целое или слово "EXP", целое => ()`

печатает вещественное число с заданным числом знаков до (второй аргумент) и после (третий аргумент) запятой. Если вторым аргументом является слово `"EXP"`, то число печатается в экспоненциальном формате; третий аргумент задает число знаков в мантиссе.

Функция

`PRSTRING ∈ цепочка литер => ()`

печатает цепочку литер без окаймляющих ее кавычек.

<!-- PDF page 14: printed pages 24–25 -->

Синтаксический идентификатор `=>` (печатающая стрелка) вызывает печать всех элементов стека, начиная с нижнего, с помощью `PR`. Печать начинается с новой строки. Сначала печатаются две звездочки, затем элементы стека, разделяемые запятыми. Стек при этом опустошается. Употребляемая внутри функции, `=>` печатает (и удаляет из стека) лишь верхний элемент. При синтаксическом разборе ПОПЛАН программы `=>` эквивалентна точке с запятой, т.е. разделяет императивы. (Сказанное не относится к случаю употребления `=>` для отделения локальных выводимых параметров функции (см. Д18 в прил. к первой части).

Функции

`PRBIN, PROCT все ∈ элемент, целое => ()`

печатают свой первый аргумент в двоичном (`PRBIN`) или восьмеричном (`PROCT`) виде. Второй аргумент в обоих случаях задает число младших соответственно двоичных или восьмеричных цифр, которые необходимо напечатать.

Функция

`GENOUT ∈ функция, (литера => ()) => функция`

позволяет преобразовать любую функцию, выводящую литеры в текущий файл вывода в аналогичную функцию, выводящую литеры с помощью данного потребителя литер. Эквивалентное описание этой функции на ПОПЛАНе таково:

```pop2
function GENOUT T C;
  lambda T CUCHOUT; .T end (% T, C %)
end;
```

В следующем примере функция `PR1` "печатает" элементы в файл ДИМОНа в том же виде, в каком функция `PR` печатала бы их на терминале.

Пример (вывод результатов в файл ДИМОНа).

```pop2
vars OUT PR1 NL1;
[ДО ИВАНОВ ФАЙЛ].POPMESS -> OUT;
GENOUT(PR, OUT) -> PR1;
GENOUT(NL, OUT) -> NL1;
PR1([299910001 IS A.PRIME.NUMBER]); 1.NL1;
forall X 0.0 0.1 2.01 X.PR1; X.SIN.PR1; X.COS.PR1; 1.NL1
close;
comment       в файл ФАЙЛ выведен список и таблица тригонометричес-
ких функций. Теперь закроем файл вывода;
PR1 (TERMIN);
```

*Замечание о локальных переменных.* Реально существующие в ПОПЛАН-системе функции `PRINT` и `GENOUT` несколько отличаются от приведенных описаний на ПОПЛАНе: они не имеют локальных идентификаторов, которые могли бы использоваться в ПОПЛАН-программе. Поэтому нежелательный эффект, который мог бы произойти, если, скажем, аргумент функции `GENOUT` использует глобальный идентификатор `T`, на самом деле не происходит. Это замечание в равной мере относится к описанным ниже функциям `APPLY` и `ITEMREAD`.

### 8.5. Поставщики элементов. Работа транслятора

Последовательность литер, образующая программу на ПОПЛАНе, может быть разбита на группы литер (см. Д49 в прил. к первой части). Одна группа изображает один элемент текста, который может быть неотрицательным целым или вещественным числом, словом или цепочкой литер. Группы литер разделяются пробелами или переводами строк в любом количестве. Можно записать две группы литер подряд без разделителя, если первая литера второй группы не может быть отнесена к первой группе. Так, два целых числа 1 и 2 следует разделить, 12 означает уже целое число "двенадцать", а, скажем, число 1 и слово X можно записать рядом; запись 1X эквивалентна 1 X.

Стандартная функция

`INCHARITEM ∈ (() => литера) => (() => элемент текста)`

позволяет получить поставщик элементов текста из некоторого файла, имея поставщик литер из этого файла. Для выделения группы литер поставщик литер, являющийся аргументом `INCHARITEM`, должен прочитать несколько (1 или 2) литер после нужной группы литер. Эти литеры запоминаются в буфере, имеющемся у поставщика элементов текста, чтобы использовать их для образования следующего элемента текста. Этот механизм следует учитывать, если поставщик литер, к которому была применена функция `INCHARITEM`, независимо используется еще где-нибудь.

Стоп-литера, выданная поставщиком литер, рассматривается как отдельная группа литер и приводит к тому, что поставщик элементов текста выдает значение `TERMIN` (см. § 7.3).

<!-- PDF page 15: printed pages 26–27 -->

Вся ПОПЛАН-программа, обрабатываемая транслятором, представлена в виде одного или нескольких списков элементов текста. Первый из них (тот, который обрабатывается в данный момент) находится в переменной `PROGLIST`, а список всех остальных списков — в переменной `NEXTCH`. Первоначально в `NEXTCH` заносится пустой список, а в `PROGLIST` `FNTOLIST(INCHARITEM(CHARIN))` (список элементов текста стандартного файла ввода). Эти же присваивания выполняются стандартной функцией `SETPOP`, которая, таким образом, переключает трансляцию на стандартный файл ввода. Переменные `PROGLIST` и `NEXTCH` незащищенные, и их значения могут изменяться пользователем, желающим транслировать программу, генерируемую нестандартным образом. Для получения очередного элемента текста из списков `PROGLIST` и `NEXTCH` имеется функция

`ITEMREAD ∈ () => элемент текста`

Эта функция выдает в качестве результата первый элемент списка `PROGLIST` (удаляя его из списка). Если `PROGLIST` пуст, то в `PROGLIST` заносится первый элемент списка `NEXTCH`. Если же при обращении к `ITEMREAD` оба списка `PROGLIST` и `NEXTCH` пусты, то происходит выход из ПОПЛАН-системы. Если элемент, выбранный функцией `ITEMREAD` из списка `PROGLIST`, окажется макроидентификатором, перед которым не стоит слово `nonmac`, то происходит выполнение соответствующей функции, после чего снова выбирается первый элемент списка `PROGLIST`. Функция `ITEMREAD` имеет побочное влияние на список `PROGLIST`. Приведем эквивалентное (с учетом замечания о локальных переменных на стр. 25) описание функции `ITEMREAD` на ПОПЛАНе.

```pop2
function STOP; СЛУЧ(13) end;
   comment    функция STOP вызывает выход из ПОПЛАН-
системы;
function GETHD => RES;
  M: if PROGLIST.NULL then
       if NEXTCH.NULL then .STOP close;
       NEXTCH.DEST -> NEXTCH -> PROGLIST;
       goto M
     close;
     HD(PROGLIST) -> RES;
     if PROGLIST.TL.NULL then FALSE -> PROGLIST.HD;
        lambda; end -> PROGLIST.TL;
        comment       о динамических списках см. § 7.3;
     else PROGLIST.TL.HD -> PROGLIST.HD;
          PROGLIST.TL.TL -> PROGLIST.TL
     close
end;
function ITEMREAD; vars X;
  L: .GETHD -> X;
     if X = "nonmac" then .GETHD
     elseif X.ISWORD and X.IDENTPROPS = "macro"
        then X.VALOF.APPLY; goto L
     else X
     close
end;
```

Транслятор использует для получения элементов текста функцию `ITEMREAD` всегда, за исключением особо оговоренных случаев, в которых не требуется выполнение макрофункций. Тогда используется функция `GETHD`, непосредственно не доступная пользователю.

Стандартная функция

`LISTREAD ∈ () => элемент`

служит для чтения списочных констант (см. Д44 из прил. к первой части) при помощи функции `ITEMREAD`. Если первый прочитанный элемент текста совпадает с `[`, то функция `LISTREAD` читает списочную константу и результатом ее служит соответствующий список:

```pop2
vars L; .LISTREAD -> L; [[1 2] 0]
L.HD =>
** [1 2]
```

В противном случае функция `LISTREAD` работает так же, как `ITEMREAD`.

Стандартная функция

`NUMBERREAD ∈ () => число`

служит для чтения чисел со знаком или без знака при помощи функции `ITEMREAD`.

```pop2
[% (forall I 1 1 5 .NUMBERREAD close) %] -> L;
   -1 3.14&-3 +11.0 2 -7.05
L =>
 ** -1, .00314000, 11.000000, 2, -7.050000
```

<!-- PDF page 16: printed pages 28–29 -->

В отличие от `LISTREAD`, функция `NUMBERREAD`, если ей не удается прочесть именно число, заканчивается сообщением об ошибке.

Стандартная функция

`COMPILE ∈ поставщик литер => ()`

используется для трансляции текста, поступающего от заданного поставщика литер (см. пример 2 в § 8.6). Она описывается так:

```pop2
function COMPILE X;
  PROGLIST :: NEXTCH -> NEXTCH;
  X.INCHARITEM.FNTOLIST -> PROGLIST
end;
```

После выполнения `COMPILE` транслятор будет читать текст, поступающий от заданного поставщика литер, а после окончания этого текста (когда поставщик литер выдаст стоп-литеру), вернется к обработке прежнего текста.

## 9. РЕЖИМЫ РАБОТЫ

### 9.1. Непосредственное выполнение

Структура ПОПЛАН-программы описана на диаграмме 50. Отметим, что все императивы выполняются сразу после того, как транслятор прочитал соответствующую точку с запятой или печатающую стрелку. Единственным исключением является описание функции, которое сначала запоминается, а выполняется лишь при обращении к этой функции.

Если при трансляции или выполнении обнаруживается ошибка, вызывается стандартная функция

`ERRFUN ∈ элемент, целое => ()`

Она печатает сообщение (целое указывает номер ошибки и идентифицирует пояснительный текст, а элемент позволяет определить причину ошибки). После того, как `ERRFUN` закончила работу, выполняется стандартная функция `SETPOP` (см. § 9.3), возвращающая ПОПЛАН-систему в стандартное состояние.

Стандартная переменная `ERRFUN` не защищена, поэтому Вы можете по-своему реагировать на ошибки. Пусть, например, после первой же ошибки необходимо выйти из ПОПЛАНа, т.к. дальнейшая работа стала бессмысленной. Реализовать это можно следующим образом:

```pop2
vars ERR; ERRFUN -> ERR;
lambda; .ERR; СЛУЧ(13) end -> ERRFUN;
```

Если далее случится ошибка, то будет напечатано диагностическое сообщение и произойдет выход из ПОПЛАН-системы.

Для продолжения компиляции файла после ошибки можно воспользоваться стандартной функцией:

`CARRYON ∈ поставщик литер => ()`

`CARRYON(C)`, где C — поставщик литер из некоторого файла, производит в этом файле поиск слова `end` и затем компилирует остаток файла.

Функция `CARRYON` полезна, когда транслируемый файл содержит описания нескольких функций.

Чтобы была возможность применять функцию `CARRYON`, неотлаженные файлы рекомендуется транслировать следующим образом:

```pop2
vars C; [USER FILE].LIBRARY -> C;
C.COMPILE;
```

<!-- PDF page 18: printed pages 32–33 -->

(предполагается, что транслируется файл `FILE` из библиотеки ДИМОНа `USER`).

*Важное замечание.* Функция `ERRFUN` не вызывается при печати предупреждающих сообщений о повторной декларации и неопределенном идентификаторе.

### 9.2. Макро-возможности

Значением переменной, описываемой макро-идентификатором, является функция, которая применяется во время компиляции программы. Такие функции мы будем называть макро-функциями.

Описание макро-функции аналогично описанию обычной функции, только вместо слова `function` употребляется слово `macro`; у этой функции не должно быть ни формальных параметров, ни результатов. Макро-функция выполняется всякий раз, когда в программе используется соответствующий макро-идентификатор, если только он встретился не в списочной константе, слове, заключенном в кавычки, после слова `macro` в описании функции или декларации, а также после синтаксического слова `nonmac`. Если слово `nonmac` стоит перед обычным (не макро) идентификатором, оно игнорируется. В комментариях макро-свойства игнорируются.

Стандартная функция

`MACRESULTS ∈ список текстовых элементов => ()`

будучи примененной в макро-функции, присоединяет эти элементы справа к уже прочитанной части программы. Отсюда следует, что если встречается более одного обращения к `MACRESULTS`, то новый список присоединяется справа к ранее вставленным элементам. После выхода из макро-функции присоединенный текст выполняется.

Пример.

```pop2
macro M;
  MACRESULTS([[M] =>]);
  MACRESULTS([[1] =>]); end;
M
** [M]
** [1]
```

Чтобы отменить макро-идентификатор M, достаточно написать

```pop2
cancel nonmac M;
```

Макро-функция не имеет формальных параметров, но с помощью функции `ITEMREAD` можно прочитать текстовые элементы, следующие за макро-идентификатором, и тем самым сделать макро-функцию зависимой от контекста, в котором она вызывается.

Пример.

```pop2
macro S;
  vars A B;
  .ITEMREAD -> A; .ITEMREAD -> B;
  [% "SUBSCR", "(", A, ",", B, ")" %].MACRESULTS
end;
vars X; INIT(10) -> X;
3 -> S 1 X;

comment       вместо S 1 X в программу подставляется
текст SUBSCR(1,X);
SUBSCR(1,X) =>
** 3
S 1 X =>
** 3
```

Заметим, что `ITEMREAD` выполняет макро-функции, а результат функции `INCHARITEM` — нет.

Соответствие между списком текстовых элементов и ПОПЛАН-программой устанавливается следующим образом: синтаксические слова, идентификаторы и слова без кавычек представляются соответствующими словами списка. Числа и цепочки представляются числами и цепочками. Слова в кавычках представляются словом, перед которым и после которого стоит слово `"`.

### 9.3. Функции POPVAL и SETPOP

Стандартная функция

`POPVAL ∈ список текстовых элементов => элемент, ..., элемент`

выполняет список текстовых элементов, трактуя его как последова-

<!-- PDF page 19: printed pages 34–35 -->

тельность императивов. Список может содержать описания функций, присваивания и т.д. Декларация, расположенная вне тела функции, считается глобальной. Список должен заканчиваться словом `goon`.

Результатом применения функции `POPVAL` является результат выполнения последовательности императивов.

Пример.

```pop2
comment       мы хотим декларировать переменные, имена кото-
рых читаются с помощью функции ITEMREAD;
vars X Y;
.ITEMREAD -> X; .ITEMREAD -> Y;
[% "vars", X, Y, ";", "goon" %].POPVAL;
```

Стандартная функция

`SETPOP ∈ () => ()`

возвращает ПОПЛАН-систему в стандартное состояние, а именно:

выполняются присваивания

```pop2
CHAROUT -> CUCHOUT;
FNTOLIST(INCHARITEM(CHARIN)) -> PROGLIST;
NIL -> NEXTCH;
```

Происходит выход из функций, в которых мы находились в данный момент (если `SETPOP` применили в функции), однако значения всех переменных, кроме трех отмеченных выше, не изменятся. Система печатает слово `SETPOP` и выполняет следующий элемент программы.

Таким образом, в случае ошибки можно распечатать значения интересующих Вас переменных, что существенно облегчает отладку программ.

## ПРИЛОЖЕНИЕ 1. Функции, не описанные в основном тексте

`APPLY ∈ функция =>`

Заставляет выполняться функцию — свой аргумент.

Пример.

Пусть L — список функций, которые нужно последовательно выполнить. Это можно сделать при помощи инструкции

```pop2
APPLIST(L, APPLY);
```

Четыре функции перекодировки.

`CODIPC, CODPIC все ∈ литера => литера`

Напомним, что литера — это целое число в диапазоне от 0 до 255. Первая из этих функций перекодирует литеру из кода ВКД в код АЦПУ-128, вторая — из кода АЦПУ-128 в код ВКД.

`CODIPS, CODPIS все ∈ цепочка, цепочка => ();`

Функция `CODIPS` берет символы из первой цепочки, перекодирует их из кода ВКД в код АЦПУ-128 и помещает во вторую цепочку. Функция `CODPIS` действует аналогично, но перекодировка идет из кода АЦПУ-128 в код ВКД (внутренний код ПОПЛАН-системы). Описанные функции полезны, если обрабатываемая информация хранится в коде АЦПУ-128.

`COREUSED ∈ () => целое, целое`

Первый результат есть общее число ячеек свободной в данный момент памяти, второй результат — число ячеек занятой памяти. Обращение к функции `COREUSED` не вызывает сбора мусора; таким образом в число занятых ячеек, возможно войдет и память уже не доступная из программы, т.е. такая память, которой будет возвращен статус свободной после сбора мусора.

`FNCOMP ∈ функция, функция => функция`

`FNCOMP` — операция приоритета 2. Результатом ее служит функция — композиция двух функций-аргументов. Так,

`X.(F FNCOMP G)` эквивалентно `X.F.G`.

Пример (заведение массива и заполнение его числами, читаемыми из текущего файла ввода):

```pop2
vars M;
NEWARRAY([1 5], ERASE FNCOMP NUMBERREAD) -> M;
  0 -9 25 16 -2
```

`IDENTFN ∈ () => ()`

Эта функция "ничего не делает". Пример (заведение массива

<!-- PDF page 20: printed pages 36–37 -->

и заполнение его числами от 1 до 100):

```pop2
vars M;
NEWARRAY([1 100], IDENTFN) -> M;
```

`POPDATE ∈ () => цепочка литер, целое`

выдает текущую дату и время. Первый ее результат — цепочка из 8 литер вида ЧЧ.ММ.ГГ, где ЧЧ — число, ММ — месяц, ГГ — год. Второй результат `POPDATE` показывает время, прошедшее от начала суток. Единица измерения времени — 20 мсек. Можно использовать это число в датчиках случайных чисел.

`POPTIME ∈ () => вещественное`

Результатом функции `POPTIME` является вещественное число, показывающее затраченное к моменту обращения к `POPTIME` время центрального процессора в секундах.

## ПРИЛОЖЕНИЕ 4. Выход из ПОПЛАН-системы и нестандартные ситуации

ПОПЛАН-система прекращает работу, когда транслятор прочитает из файла ввода литеру "надчеркивание" (стоп-литеру). Ввод надчеркивания приводит к тому, что поставщик элементов текста, читающий литеры из данного файла ввода, возвращает в качестве своего значения элемент `TERMIN`, что, в свою очередь, вызывает окончание динамического списка `PROGLIST`, определенного с помощью этого поставщика элементов текста (см. § 7.3). Транслятор, обнаружив, что список `PROGLIST` пуст, прекратит работу (если при этом пуст также список `NEXTCH`, см. § 8.5). Поэтому для выхода из ПОПЛАН-системы следует ввести с терминала (или с перфокарт) литеру "надчеркивание".

Могут, однако, встретиться ситуации, когда одного надчеркивания будет недостаточно. Если, например, была выполнена инструкция `COMPILE(CHARIN)`, то ввод надчеркивания с терминала приведет лишь к окончанию списка, обрабатываемого в результате выполнения функции `COMPILE`, а затем транслятор начнет обрабатывать предыдущий список, запомненный в переменной `NEXTCH` (см. § 8.5), т.е. скорее всего, вновь будет читать литеры с терминала. В таком случае следует ввести надчеркивание еще раз. Более сложный случай имеет место, если пользователь написал и вызвал функцию, которая вводит литеры с терминала и (вследствие ошибки при программировании) никогда не кончается, вводя литеры в цикле. Для перехода в нормальный режим следует набрать на терминале (обязательно с начала строки) следующую группу литер:

`*###0` ⟨etx⟩.

Это вызывает динамическую ошибку, в результате обработки которой ПОПЛАН-система приходит в стандартное состояние. Затем можно продолжить работу или выйти из ПОПЛАН-системы, введя надчеркивание. Очень похожая картина наблюдается, если пользователь случайно набрал на терминале литеру "кавычка", в результате чего транслятор воспринимает все последующие литеры (в том числе и надчеркивание) как компоненты цепочки литер (см. § 7.5). Внешне ПОПЛАН-система не реагирует ни на какую литеру, все время выдавая приглашение на ввод. Выход из такого состояния обеспечивается вводом литеры "кавычка", завершающей цепочку. Можно также поступить, как в предыдущем случае.

Еще одна нестандартная ситуация — зацикливание при выводе: программа непрерывно выводит литеры на терминал и не кончается. Для прекращения работы программы следует нажать на клавишу прерыва вывода (на "Видеотоне" — клавиша ⟨ERASE⟩ или ⟨DEL⟩ в русском режиме). Это вызывает выполнение функции `SETPOP`, возвращающей ПОПЛАН-систему в стандартное состояние (см. § 9.3).

## Приложение 5. Программа отладки DEBUG

Программа `DEBUG` позволяет следить за входами и выходами из функций в процессе счета, а также распечатывать аргументы и результаты функций.

Чтобы воспользоваться ею, достаточно скомпилировать файл `DEBUG` в библиотеке `POPLIB` из ДИМОНа:

```pop2
[POPLIB DEBUG].LIBRARY.COMPILE;
```

Затем нужно специфицировать те функции, за которыми вы хотите следить в процессе счета, при помощи предложения `SPEC`. Синтаксис предложения `SPEC` очень похож на синтаксис заголовка функции (ср. с Д20 из прил. к первой части):

```text
                                    ┌─────────────────────────────────────────────┐
                                    │                                             ↓
→ SPEC →┬→ ИДЕНТИФИКАТОР →┬─────────┴→ => →┬───────────────────────────────┬───────┴→
        ↑                │                 ↑                               │
        └────────────────┘                 └───── ИДЕНТИФИКАТОР ←──────────┘
```

Пример 1. Функцию

```pop2
function ADD X Y; X+Y end;
```

можно специфицировать предложением

```pop2
SPEC ADD A B => SUM;
```

Из примера 1 видно, что

1) Параметры функции в предложении `SPEC` не обязательно обозначать так же, как они были обозначены в описании функции.
2) В предложении `SPEC` могут присутствовать локальные выводимые, даже если их не было в заголовке функции. Слова `=> SUM` говорят о том, что нужно печатать результат функции.

Пример 2. Пусть функция F имеет 4 аргумента и три результата. Ее можно специфицировать предложением

```pop2
SPEC F A B C D => X Y Z;
```

Если вы хотите, чтобы печатались только два последних аргумента и один последний результат, то специфицируйте F предложением

```pop2
SPEC F C D => Z;
```

Если вы не хотите печатать, скажем, второй и третий аргументы и два последних результата, то запишите на их месте звездочки:

```pop2
SPEC F A * * D => X * *;
```

Функции, за которыми вы хотите следить, после того, как они специфицированы, нужно указать еще в предложении `BUG`:

```pop2
BUG ADD;
comment будет отслеживаться функция ADD;
BUG F1 F2 F;
comment кроме ADD будут отслеживаться еще функции F1, F2, F;
```

Чтобы включить программу отладки, необходимо еще выполнить присваивание

```pop2
TRUE -> DEBUG;
```

Итак, для того, чтобы отслеживать функцию, ее нужно специфицировать предложением `SPEC` и указать в предложении `BUG`. Для включения программы отладки нужно присвоить переменной `DEBUG` значение, отличное от `FALSE`.

При входе в отслеживаемую функцию всякий раз с новой строки печатается значок `>`, затем имя функции и значения аргументов. При выходе из нее печатается значок `<`, имя функции и результаты.

При обращении к функции `ADD(2,3)` из примера 1 получится распечатка

```text
>ADD; A=2, B=3,
<ADD; SUM=5,
```

Для отмены отладки отдельных функций служит предложение `UNBUG`:

```pop2
UNBUG F1 F;
comment отменяется отладка функций F1, F;
```

Для возобновления отладки этих функций достаточно лишь снова указать их в предложении `BUG`, не специфицируя их вторично:

```pop2
BUG F;
comment вновь включили отладку функции F;
```

Для того, чтобы вообще отменить распечатки отладчика, нужно выполнить присваивание

```pop2
FALSE -> DEBUG;
```

При этом все выполненные ранее предложения `SPEC`, `BUG`, `UNBUG` остаются в силе, и в любой момент можно снова включить печать отладчика присваиванием `TRUE -> DEBUG`.

Аргументы и результаты функций программа отладки печатает с помощью функции `DEBPR`. Вначале `DEBPR` совпадает с `PR`, но переменной `DEBPR` можно присвоить другую функцию печати. Важно

<!-- PDF page 25: printed pages 46–47 -->

чтобы она имела один аргумент и не имела результатов, иначе результат работы отладчика непредсказуем.

При каждом входе в функцию соответствующая распечатка отладчика сдвигается на одну позицию вправо, при выходе — возвращается на одну позицию влево. Таким образом, листинг отладчика получается "ступенчатым", и распечатки, соответствующие входу и выходу из данной функции начинаются с одной и той же позиции. Текущая позиция, с которой нужно начать очередную распечатку, хранится в глобальной переменной `DEBSP`. Вначале `DEBSP=0`. После ошибки значение переменной `DEBSP` может оказаться > 0, и при последующих обращениях к отлаживаемым функциям распечатки начнутся не с самой левой позиции, а где-то правее. Чтобы избежать этого эффекта, после ошибки нужно выполнить присваивание `0 -> DEBSP`.

В принципе пользователь может располагать переменной `DEBSP` по своему усмотрению.

(Номер строки соответствует последней восьмеричной цифре кода литеры.)

ПС — перевод строки.

␣ — пробел.

Для работы с литерами необязательно знать их коды. Поставщики текстовых элементов (в том числе функция `ITEMREAD`, используемая транслятором, а также функции, полученные в результате применения `INCHARITEM`) воспринимают сочетание литер

"подчеркивание" "произвольная литера"

как целое число — код "произвольной литеры".

```pop2
_A =>
** 65
_B.CUCHOUT;
B
vars S; INITC(4) -> S;
_C -> SUBSCC(1,S); _A -> SUBSCC(2,S);
_T -> SUBSCC(3,S); _  -> SUBSCC(4,S); S =>
** 'CAT '
```
